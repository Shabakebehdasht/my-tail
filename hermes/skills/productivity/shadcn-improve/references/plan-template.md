# Handoff Plan Template

Every plan is written for an executor model with **zero context**. Three properties make it executable:
1. Self-contained context — everything needed is in the file.
2. Verification gates — every step ends with a command and expected result.
3. Hard boundaries and escape hatches — explicit out-of-scope list and STOP conditions.

File naming: `plans/NNN-short-slug.md`

---

## Template

```markdown
# Plan NNN: <Imperative title>

> **Executor instructions**: Follow this plan step by step. Run every
> verification command and confirm the expected result before moving to the
> next step. If anything in the "STOP conditions" section occurs, stop and
> report — do not improvise.
>
> **Drift check (run first)**: `git diff --stat <planned-at SHA>..HEAD -- <in-scope paths>`
> If any in-scope file changed since this plan was written, compare the
> "Current state" excerpts against the live code before proceeding.

## Status

- **Priority**: P1 | P2 | P3
- **Effort**: S | M | L
- **Risk**: LOW | MED | HIGH
- **Depends on**: plans/NNN-*.md (or "none")
- **Category**: bug | security | perf | tests | tech-debt | migration | dx | docs | direction
- **Planned at**: commit `<short SHA>`, <YYYY-MM-DD>

## Why this matters

2–5 sentences. Written so the executor understands the intent.

## Current state

- Relevant files with one line on role each.
- Code excerpts with `file:line` markers.
- Repo conventions that apply (with exemplar file pointer).
- Documented vocabulary/design constraints, inlined.

## Commands you will need

| Purpose   | Command                  | Expected on success |
|-----------|--------------------------|---------------------|
| Install   | `composer install`       | exit 0              |
| Typecheck | `php artisan ...`        | exit 0              |
| Tests     | `composer test`          | all pass            |
| Lint      | `vendor/bin/pint --dirty`| exit 0              |

## Scope

**In scope**:
- file paths

**Out of scope** (do NOT touch):
- file paths with reasons

## Steps

### Step 1: <imperative title>

What to do, precisely.

**Verify**: `<command>` → <expected output>

### Step 2: ...

## Test plan

- New tests to write, which file, covering which cases.
- Which existing test to use as structural pattern.
- Verification: `<test command>` → all pass.

## Done criteria

Machine-checkable. ALL must hold:

- [ ] Tests pass
- [ ] No files outside the in-scope list modified

## STOP conditions

Stop and report back if:
- Code doesn't match excerpts (drifted since plan written).
- A step's verification fails twice.
- Fix appears to require touching an out-of-scope file.
- A key assumption is false.

## Maintenance notes

- What future changes will interact with this.
- What a reviewer should scrutinize.
- Follow-up explicitly deferred (and why).
```
